# Security model and assumptions

The intended environment contains synthetic transactions only. SentinelML does not execute external payments, block accounts, or claim regulatory certification.

Rails uses bcrypt password hashes, encrypted/signed HttpOnly cookie sessions, SameSite=Lax, and CSRF tokens. The cookie references a hashed, expiring database session; logout, disabling a user, role changes and password changes revoke affected sessions. The last active administrator cannot be removed. Session fixation is mitigated by resetting the session on login. Set SECURE_COOKIES=true and terminate TLS before using a remote environment. The frontend obtains a CSRF token from the session endpoint and attaches it to mutations. Login attempts are limited through Redis and fail closed if Redis is unavailable. Passwords, API keys, and authorization parameters are filtered from Rails logs.

Authorization is server-side through Pundit and tenant-scoped ActiveRecord relations. Viewers can read but cannot generate demo traffic or modify alerts/cases; risk policy mutations require admin or risk_manager. Case assignment verifies the chosen user belongs to the organization and has a participating role. Only the demo organization may use its configured demo ingestion key.

Ingestion keys are SHA-256 digests in the service database. Use high-entropy random production keys. Rate limiting is Redis-backed and atomic, with 600 requests/minute per key. Bodies are limited to 16 KiB. Strict decoding refuses unknown fields. Idempotency is organization scoped and detects conflicting payloads. The database also constrains positive monetary amounts and device trust.

No PAN, card-number, CVV, password, or bank credential fields belong in transaction payloads. Merchant and account token fields are untrusted strings and must be synthetic/tokenized. Never paste actual credentials into these fields. Application logs should be reviewed before production because framework SQL/error logging can expose business metadata.

Compose exposes only the gateway and local monitoring ports on 127.0.0.1. PostgreSQL, Redis, Kafka, inference metadata, and service metrics remain on the internal network. Their default transport is plaintext; use authenticated TLS, network policies, secrets management, and separately provisioned accounts outside local development. Caddy applies security headers. The initial CSP permits inline Next.js scripts/styles; use nonces and a stricter policy before production.

Local-only credentials are documented openly and must be replaced. Service database roles share the local database password but have separate database access. Never reuse this topology or credentials for real financial data. Compose init SQL only runs on a new PostgreSQL volume; changing .env does not rotate an existing database role password.

Administrators can create/rotate/revoke random 256-bit ingestion keys. Raw secrets appear once; list APIs and audits contain metadata only. The demo environment key is explicitly environment-managed. Profile/notification preferences, in-app notifications and automated retention are implemented. Retention holds open/recently updated investigations and pending publication, asks both owning services to purge eligible IDs, and removes the control projection only after acknowledgements. Organization locking coordinates review mutations and retention; reruns tolerate a partial remote purge.

Users belong to one organization; the organization badge reflects that membership. Invitations, self-service recovery, MFA/SSO, externally delivered email/SMS notifications and a user-facing session inventory are outside this local demonstration. Kubernetes references operator-provided secrets and TLS; no remote infrastructure or certificates have been provisioned. No independent penetration test, regulatory certification or production capacity guarantee is claimed.

Dependency verification uses npm audit, pip-audit and scripts/audit_dependencies.py against OSV. Rust's SQLx lockfile includes optional MySQL/RSA entries even when disabled; the captured production cargo tree excludes both. Evaluate the selected graph when interpreting RUSTSEC-2023-0071, and reassess it if adding MySQL. See verification.md for exact executed results.
